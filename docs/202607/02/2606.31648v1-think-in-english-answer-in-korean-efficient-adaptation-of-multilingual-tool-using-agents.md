## 摘要
我们提出了LuckyStar 111B，一个1110亿参数的混合推理模型，由Cohere与LG CNS合作开发，用于在实用内存和服务器限制下服务于韩英双语企业智能体。该模型基于Cohere完全后训练的Command A模型进行训练，而非重新预训练，并使用前导条件化在简洁的非推理行为与较长的面向工具推理之间切换。我们研究了四种高效扩展工具使用智能体的选择：多语言监督微调、针对多步工具使用任务的可验证奖励强化学习、面向韩语用户响应的语言一致性奖励，以及用于单GPU服务的4位量化。适配后的模型在数学推理、函数调用和智能体自然语言到SQL（NL2SQL）性能方面有所提升，同时保持了通用的韩语和英语指令遵循质量。这些结果为在内存受限部署下将后训练的多语言模型适配到可验证的智能体工作流提供了实用方案和失败模式分析。

## Abstract
We present LuckyStar 111B, a 111B-parameter hybrid reasoning model developed through a collaboration between Cohere and LG CNS for Korean-English enterprise agents under practical memory and serving constraints. The model trains from Cohere's fully post-trained Command A model rather than a new pretraining run, and uses preamble conditioning to switch between concise non-reasoning behavior and longer tool-oriented reasoning. We study four choices for scaling tool-using agents efficiently: multilingual supervised fine-tuning, reinforcement learning with verifiable rewards for multi-step tool-use tasks, language-consistency rewards for Korean user-facing responses, and 4-bit quantization for single-GPU serving. The adapted model improves mathematical reasoning, function calling, and agentic natural-language-to-SQL (NL2SQL) performance while preserving general Korean and English instruction-following quality. These results provide a practical recipe and failure-mode analysis for adapting post-trained multilingual models to verifiable agentic workflows under memory-constrained deployment.

## 1. 论文的核心问题与整体含义（研究动机和背景）
- **核心问题**：在多语言（尤其是韩英双语）企业级智能体应用场景下，如何在有限的内存和服务预算约束下，高效地将一个已经后训练的多语言基础模型适配为具备推理和工具使用能力的智能体。
- **背景**：企业助手需要处理私有数据、调用工具（如SQL、检索），并用用户语言（韩语）回答，但底层数据（如数据库Schema、文档）往往是英语的。现有后训练模型（如Command A）缺乏专用于多语言推理和工具使用的行为。作者希望避免从头训练，而是通过低成本适配，使单一模型支持两种模式：简洁的非推理模式与面向工具的长推理模式。

## 2. 论文提出的方法论
- **核心思想**：基于Cohere的Command A（111B参数）后训练模型，通过三阶段适配流水线，并采用**前导条件化**（preamble conditioning）让同一模型权重在不同推理深度之间切换。
- **关键技术细节**：
  - **三阶段流水线**：
    1. **混合监督微调（Hybrid SFT）**：约80%为推理示例（使用推理前导词），20%为非推理示例（使用简洁前导词）。推理数据涵盖数学、代码和工具使用，通过多种模型生成候选推理轨迹并与答案匹配后保留正确轨迹。
    2. **可验证奖励的强化学习（RLVR）**：使用REINFORCE Leave-One-Out (RLOO)和定制奖励函数。针对NL2SQL，先通过拒绝采样引导冷启动，然后使用规则或LLM验证器给出二元奖励。对韩语提示引入**语言一致性惩罚**（公式(1)）：如果最终答案语言与提示语言不匹配，扣0.5奖励。超过32k token的滚出被过滤而非给予零奖励，避免教模型提前结束。
    3. **离线偏好对齐（DPO）**：使用低学习率DPO偏好对，减少RLVR带来的冗余，保持指令跟随质量。
  - **混合语言推理策略**：根据实验发现，韩语提示下英语推理优于韩语推理。因此采用“用英语思考，用用户语言回答”策略：生成英语推理轨迹，但强制最终答案转为韩语。人工审核翻译质量，确保自然度。
  - **量化部署**：使用4-bit量化（从FP8降至4-bit）使模型可在单张80GB H100 GPU上部署。

## 6. 论文的主要结论与发现
- LuckyStar 111B在数学推理、函数调用和NL2SQL上显著优于基础模型Command A，并在韩英通用基准上保持竞争力。
- “用英语思考，用韩语回答”的混合语言策略有效，语言一致性惩罚大幅减少韩语提示下答案漂移为英语（从12.2%降至0.8%）。

- 冷启动拒绝采样对工具使用RL至关重要，否则NL2SQL初始准确率不足1%，RL无法获得有效信号。
- 后续DPO可以有效抵消RLVR产生的冗余，改进简洁性。

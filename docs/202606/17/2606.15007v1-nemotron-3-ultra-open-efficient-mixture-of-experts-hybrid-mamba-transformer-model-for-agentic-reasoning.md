## 摘要
我们推出了Nemotron 3 Ultra，一个总参数量为5500亿、激活参数量为550亿的混合专家（MoE）混合Mamba-注意力语言模型。我们在20万亿文本令牌上预训练了Nemotron 3 Ultra，然后将其上下文长度扩展到100万令牌，并采用监督微调（SFT）、强化学习（RL）和多教师在线策略蒸馏（MOPD）进行后训练。Nemotron 3 Ultra是我们目前最强大的模型，采用了多项关键技术——LatentMoE、多令牌预测（MTP）、NVFP4预训练、多环境RLVR、MOPD和推理预算控制。与当前最先进的公开可用大语言模型相比，Nemotron 3 Ultra的推理吞吐量提升高达约6倍，同时保持同等精度。最先进的精度、高推理吞吐量和100万令牌的上下文长度使Nemotron 3 Ultra成为长时间自主智能体任务的理想选择。我们在HuggingFace上开源了基础模型、后训练模型和量化检查点，以及训练数据和配方。

## Abstract
We introduce Nemotron 3 Ultra, a 550 billion total and 55 billion active parameter Mixture-of-Experts Hybrid Mamba-Attention language model. We pre-trained Nemotron 3 Ultra on 20 trillion text tokens, then extended the context length to 1M tokens, and post-trained using Supervised Fine Tuning (SFT), Reinforcement Learning (RL), and Multi-teacher On-Policy Distillation (MOPD). Nemotron 3 Ultra is our most capable model yet, employing multiple key technologies - LatentMoE, Multi Token Prediction (MTP), NVFP4 pre-training, multi-environment RLVR, MOPD, and reasoning budget control. Nemotron 3 Ultra achieves up to ~6x higher inference throughput as compared to state-of-the-art publicly available LLMs while attaining on-par accuracy. The state-of-the-art accuracy, high inference throughput, and 1M token context length make Nemotron 3 Ultra ideal for long-running autonomous agentic tasks. We open-source the base, post-trained, and quantized checkpoints, along with the training data and recipe on HuggingFace.

- **核心问题**：大型语言模型（LLM）的应用正在从简单的对话机器人转向能够长时间自主执行任务的智能体（如编写代码、进行研究、完成复杂多步骤流程）。这类场景要求模型同时具备 **高推理精度** 和 **高推理吞吐量**（低延迟、高并发），而现有的公开模型往往在两者之间难以取得平衡——大参数模型精度高但推理慢，小参数模型速度快但能力不足。
- **整体含义**：Nemotron 3 Ultra 旨在打破这一权衡，通过架构创新和训练技术，构建一个**总参数量 550B、激活参数量 55B** 的混合专家（MoE）模型，在保持 SOTA 级别精度的同时，将推理吞吐量提升至公开模型的 6× 左右，尤其适用于长时间运行的自主智能体任务。同时，该论文开源了所有检查点、训练数据和配方，为社区提供了可复现的高效大模型范本。

## 2. 方法论
### 2.1 核心思想
- 融合 **混合 Mamba-Attention 架构**、**LatentMoE** 和 **多令牌预测（MTP）**，在保持模型表达能力的同时大幅降低注意力计算开销和 KV 缓存占用。
- 预训练使用 **NVFP4（4 位浮点）** 从零开始训练 20 万亿 tokens，实现显著的内存与带宽节省。
- 后训练采用 **SFT → 统一 RLVR → 多教师在线策略蒸馏（MOPD）** 的流水线，通过领域专用教师模型逐步提升代理、推理等综合能力。
- 引入 **推理预算控制**（reasoning effort control），在推理时动态调节精度-计算量折中。

| **长上下文扩展（LC-Phase）** | 连续预训练 33B tokens，1M 上下文长度，混合长文档 QA 和 phase-2 数据，并保留 8% 的 4K 短序列步数维护短基准性能。 |
| **SFT** | 两阶段：阶段一 294k 序列长度，阶段二 515k 序列长度，并加入长上下文数据。涵盖搜索、终端使用、代码、数学、科学、对话、安全等多领域。 |
| **RLVR** | 统一可验证奖励训练，覆盖 10+ 环境（代理、推理、代码、安全性等），使用非对称 GRPO 算法，全局 batch size 8192，每 prompt 16 个 rollout。 |
| **MOPD** | 多教师在线策略蒸馏：10 余个领域专用教师（SWE、终端、搜索、办公、Chat、STEM 等）对学生生成的 rollout 提供令牌级密集监督信号。两轮迭代，结合 MOPD Warmup 缓解分布不匹配。 |
| **量化** | 最终采用 NVFP4 权重 + FP8 Mamba 线性层 + BF16 注意力层 + 4/6 自适应块量化策略，整体 5.03 比特/元素（BPE），精度几乎无损。 |
| **Mamba SSM 缓存优化** | 使用 FP16 + 随机舍入，或 INT8 块量化 + 周期性检查点（检查点间隔 8），大幅减少 SSM 缓存占用。 |

### 2.3 公式与算法（文字说明）
- **MOPD 损失函数**：学生在每个前缀位置上最小化与其对应教师之间的反向 KL 散度 \( D_{KL}(\pi_\theta \| \pi_{T_i}) \)；在异步设置中，使用行为策略与近端策略的比值 \( c_t \)，并对策略比 \( r_t(\theta) \) 进行 PPO 式裁剪。
- **MTP Boosting 损失**：固定 backbone，仅更新 MTP 头，以温度 \( T=2 \) 的 forward KL 散度匹配 backbone 的 logits 分布，训练时模拟推理时的噪声（使用前 MTP 步产生的隐状态作为输入）。
- **量化算法**：针对 NVFP4 权重，选择 4/6 自适应网格（每个微块选择 4 值或 6 值网格），比单纯 max 或 MSE 校准更优。

## 6. 主要结论与发现
1. **精度**：Nemotron 3 Ultra 在大多数基准上达到或超越同量级公开模型，尤其在代理任务（Terminal Bench、SWE-Bench、BrowseComp）和竞赛级推理（IOI 2025 超人类前三、IMO 高得分）。
2. **吞吐量**：在 decode-heavy 场景（8K/64K）下，吞吐量是 GLM-5.1 的 5.9×、Kimi-K2.6 的 4.8×、Qwen-3.5 的 1.6×；在 prefill-heavy 场景下与 Qwen-3.5 持平或略优（图15）。
3. **MOPD 有效性**：在代理任务上恢复教师精度的 60~170%，但在纯推理任务（HLE）上提升有限（仅 16.9%），表明学生对少见推理路径采样不足时蒸馏效率降低。
4. **量化**：NVFP4 量化（W4A4）与 BF16 相比几乎无精度损失（表18），长上下文基准中甚至略有提升。
5. **MTP Boosting**：将平均接受长度从 4.39 提升至 4.58（贪心解码），推测解码速度提升约 3~6%。
6. **训练稳定性**：NVFP4 预训练中出现两次发散，分别由梯度累积精度不足和未知原因导致，通过调整 FP32 还原和早期学习率退火得以解决（图5、6、7）。

## 7. 优点（续）
- **推理效率压倒性**：在同等精度下，推理吞吐量最高达 6×，且支持 1M 上下文，**兼顾长上下文与实时交互**。这得益于稀疏注意力、Mamba SSM 缓存优化和 NVFP4 量化的协同设计。
- **完全开源**：开源所有检查点（预训练、后训练、量化版本）、训练数据（3个新增数据集）和完整训练配方，降低了社区复现和二次开发的门槛。
- **训练数据与配方公开**：除常见数据外，新增了法律、代码、专业领域数据，并详细描述了数据合成、质量过滤、多语言扩展等流程，对数据工程有直接参考价值。
- **量化方案实用性强**：NVFP4 量化以极低精度损失（<0.4% 预训练损失差距）实现了近 4× 的内存节省，且量化算法（自适应网格、随机 Hadamard 变换）可迁移至其他模型。
- **后训练流水线模块化**：SFT → 统一 RLVR → MOPD 的设计允许灵活替换或扩展领域教师，便于在特定场景下快速提升能力。

## 8. 缺点与局限性
1. **训练成本极高**：预训练 20T tokens（NVFP4），后训练 RL 使用 3K+ GPU 集群，MOPD 需要维护 10+ 领域教师模型。整体算力需求远超大多数研究团队能承受的范围，可复现性主要适用于大型机构。
2. **MOPD 在纯推理任务上提升有限**：在 HLE 上仅恢复教师精度的 16.9%，说明蒸馏对深度推理路径的覆盖不足。对于需要独特多步推理链的任务（如复杂数学证明），在线蒸馏可能不如直接使用教师输出或增加采样多样性。
3. **NVFP4 预训练不稳定**：训练过程中出现两次发散，虽已通过调参解决，但细节（如梯度累积精度）对其他团队复现仍有风险。低精度训练的稳定性仍需更系统的研究。
4. **部分基准未公开**：如 BrowseComp、TauBench 等，导致社区无法完全独立验证结果。对比模型的部分参数（如 Qwen-3.5 的推理配置）可能存在微小差异，影响公平性。
5. **MoE 架构的部署复杂性**：虽然推理吞吐量高，但 550B 总参数（55B 激活）的 MoE 在分布式部署时仍需精细的专家负载均衡和通信优化，小团队难以直接受益。
6. **长上下文扩展的泛化性**：长上下文性能仅在特定基准（RULER 1M、AA-LCR）上验证，而在长文档问答、多跳推理等真实场景中的泛化能力仍需更多测试。

## 9. 启示与贡献
- **架构方向**：混合 Mamba-Attention 证明了在超大规模 MoE 中，用状态空间模型替代大部分注意力层可以显著降低 KV 缓存，同时保持甚至提升长上下文能力。这一思路可能成为未来高效 LLM 的主流选择。
- **训练范式**：NVFP4 预训练的成功表明，可以在不牺牲太多精度的情况下大幅降低训练内存和带宽，从而在相同资源下训练更大模型或更长序列。低精度训练有望从“后期压缩”走向“原生低精度”。
- **蒸馏技术**：MOPD 的多教师在线策略蒸馏为吸收多个专家模型能力提供了有效框架，其异步设计和 warmup 策略缓解了分布偏移问题。未来可探索自动选择教师或动态调整蒸馏权重的方案。
- **推理效率**：本文揭示了一个重要权衡：对于长时间运行的智能体，模型带宽（而非浮点运算）常成为瓶颈。因此，减少每 token 的显存访问（如小激活、低精度、长接受长度）比单纯降低计算量更重要。
- **开源生态**：完整开源和详细文档将加速社区在智能体、量化、MoE 等方向的研究，特别是为中小团队提供了可参考的设计蓝本。

## 10. 个人思考与延伸问题
- **能否进一步压缩**：若将 Mamba 层全面替换为更高效的 SSM 变体，或使用更激进的量化（如 3-bit 或二进制权重），是否能在不显著降低推理精度的前提下达到更大吞吐量？
- **MOPD 的教师选择**：本文使用了 10+ 领域教师，但未讨论教师之间的冲突或冗余。是否可以通过稀疏门控或注意力分配来减少教师数量，降低训练开销？
- **推理预算控制**：论文提到“reasoning effort control”但未详述机制。未来可以研究如何在推理时动态选择是否启用 MTP、调整采样温度或切换量化精度，以自适应不同难度任务。
- **安全性**：论文虽提及了安全训练数据，但未详细评估模型的偏见、越狱等风险。作为开源模型，其安全微调的有效性和鲁棒性值得进一步测试。

## 摘要
文本到SQL系统通常通过查询级执行正确性进行评估，但这种终端信号几乎无法指导中间SQL决策是成功还是失败。令牌级密集监督也不适用：SQL令牌与完整的语义决策不对齐，可能惩罚执行等效查询，且难以大规模可靠标注。因此，我们提出CAPER，通过对SQL抽象语法树进行反事实干预自动推导子句级监督，实现奖励建模的根因错误定位；所得数据用于训练轻量级Clause-PRM——CAPER-9B，为策略优化和候选验证提供子句边界反馈。在BIRD和Spider上的实验表明，子句对齐监督不仅提高了执行准确率（相比GPT-5.4相对EX提升达15.3%），还增强了故障定位能力，在保留故障上达到84.53%准确率和90.60% MRR。我们的项目页面为https://github.com/banrichard/RL-NL2SQL。

## Abstract
Text-to-SQL systems are typically evaluated by query-level execution correctness, but this terminal signal provides little guidance about which intermediate SQL decision caused success or failure. Token-level dense supervision is also ill-suited: SQL tokens do not align with complete semantic decisions, can penalize execution-equivalent queries, and are difficult to label reliably at scale. We therefore propose CAPER, which automatically derives clause-level supervision via counterfactual intervention on the SQL abstract syntax tree, enabling root-cause error localization for reward modeling; the resulting data is used to train CAPER-9B, a lightweight Clause-PRM that provides clause-boundary feedback for policy optimization and candidate verification. Experiments on BIRD and Spider show that clause-aligned supervision not only improves execution accuracy, achieving up to a 15.3% relative EX improvement over GPT-5.4, but also strengthens failure-localization capability, reaching 84.53% accuracy and 90.60% MRR on held-out failures. Our project page is at https://github.com/banrichard/RL-NL2SQL.

## 1. 核心问题与整体含义（研究动机与背景）
- **问题**：当前 Text-to-SQL 系统主要依赖**查询级执行正确性**（即最终 SQL 是否返回正确结果）作为评估信号，但这种“终端信号”无法告诉模型是哪个中间 SQL 决策导致了成功或失败，存在**信用分配难题**。
- **已有监督的不足**：
  - 执行级奖励：太稀疏，无法定位错误根因。
  - Token 级密集奖励：与 SQL 的语义决策不对齐（如逗号、别名等不构成完整语义单元），容易惩罚等效查询，且难以可靠地大规模标注。
- **核心动机**：寻找介于两者之间的**中间粒度**——**子句级**监督（如 SELECT、FROM/JOIN、WHERE、GROUP BY 等）。子句是 SQL 语义上完整的单元，且错误通常源于少数错误子句。
- **整体含义**：通过自动构造子句级过程监督信号，可以同时提升执行准确率、故障定位能力和候选验证效果，为 Text-to-SQL 的强化学习提供更有效的反馈。

## 2. 方法论：核心思想、关键技术细节、公式/算法流程
### 核心思想
- 提出 **CAPER 框架**：利用**反事实干预**（counterfactual intervention）自动化地从查询级执行结果中提取子句级奖励标注。
- 基于标注数据训练轻量级**子句级过程奖励模型 CAPER-9B**，并在策略优化（GRPO）中提供子句级奖励。

### 关键技术细节
1. **子句单元定义**：
   - 将 SQL 分解为语义完整的顶层子句：`SELECT`, `FROM-JOIN`, `WHERE`, `GROUP-HAVING`, `ORDER-LIMIT`, `WITH`, `WINDOW`, `SET-OP`。
   - 生成的 SQL 表示为 \( y = (u^{κ_1}_1, u^{κ_2}_2, …, u^{κ_K}_K) \)，前缀 \( p_k = (u^{κ_1}_1, …, u^{κ_{k-1}}_{k-1}) \)。

2. **自动标注流程**（算法1）：
   - 首先用 SFT 策略生成轨迹池，根据执行结果分为成功轨迹 \( T^+ \) 和失败轨迹 \( T^- \)。
   - **故障注入（Fault Injection）**：对成功轨迹的 AST 进行类型保持的突变（如换聚合函数、列名、操作符），生成新 SQL 并保留执行结果不同的样本，产生“正确子句 vs 错误子句”的偏好对。
   - **反事实干预（Counterfactual Intervention）**：对失败轨迹，找出第一个与金标不同的子句，通过最小成本 AST 编辑脚本将其修复为金标对应的子句，得到“正确子句 vs 错误子句”对。
   - 然后计算**拓扑感知的节点级奖励**（式14）：以根因节点为中心，对 AST 上的节点按最短路径距离施加高斯衰减的负奖励；子句级奖励取子句内节点最小奖励（式15），惩罚最强的错误节点。
   - 最终构建标注数据集 \( D = D^+ \cup D^- \)，每个元组包含输入、前缀、正负子句、子句类型、边缘权重。

3. **Clause-PRM 训练**：
   - 使用 margin-weighted 偏好损失（式19）训练 \( f_ψ \)，使其对正确子句给出比错误子句更高的分数。

4. **策略优化（RL）**：
   - 采用 GRPO 框架，在子句边界处引入组合奖励（式20）：格式奖励 + 子句奖励 + 终端执行奖励。
   - 计算子句级 return-to-go，并做组内标准化（式21），然后应用裁剪的 GRPO 目标（式22）。

## 6. 主要结论与发现
1. **子句级监督显著提升执行准确率**：GRPO-Clause 在 BIRD Dev 上达到 63.56% EX（P@1），相对 GPT-5.4 提升 15.3%；在 Spider Test 上达到 82.63% P@1。
2. **子句级奖励优于稀疏和 Token 级奖励**：GRPO-Clause 在所有数据上均优于 GRPO-Sparse 和 GRPO-Token，说明语义对齐的细粒度反馈比简单密集化更有效。
3. **故障定位能力强**：CAPER-9B 在保留故障上达到 84.53% Top-1 准确率和 90.60% MRR，远超执行级 RM 和大多数基线。
4. **候选验证效果稳定**：作为 verifier，CAPER-9B 在四个闭源模型的候选池上均稳定提升 EX（+0.7~+1.6 点），优于多数投票和 Exec-RM。
5. **组件的必要性**：消融表明拓扑感知传播、故障注入和反事实干预三者缺一不可，尤其是故障注入和反事实干预的缺失会导致性能断崖式下降。

## 7. 优点
- **自动化标注**：无需人工标注子句级偏好，完全从执行结果反推，可扩展。
- **语义对齐的粒度**：子句级单元既比执行级密集，又比 Token 级语义紧凑，适合 SQL 错误定位。
- **可迁移性**：CAPER-9B 不仅能优化策略，还能直接用于验证其他模型（闭源）的候选结果。
- **理论保障**：提供了拓扑感知奖励的界限分析和单调性证明（附录B）。
- **实验规范**：开源项目页面、提供算力表、资产许可声明、详细的超参数设置。

## 8. 不足与局限
- **数据集与 SQL 方言限制**：仅使用 BIRD/Spider/SYNSQL，尚未在其他领域（如企业 SQL、NoSQL 变体）验证泛化性。
- **粒度仍可能粗**：当前仅分解顶层子句，当错误发生在子句内部（如 WHERE 的一个谓词或嵌套子查询）时，定位不够精确。虽然理论上可递归扩展，但未在本文中实施。
- **仅针对 SQL 生成**：方法依赖 SQL 的结构化特性，不易直接迁移到自由文本推理或代码生成等任务。
- **计算开销大**：自动标注需要 SFT rollout、AST 解析、反事实修复、多次执行验证，比直接使用稀疏执行奖励更昂贵（虽然有复用优势）。
- **未报告统计显著性**：由于 RL 训练成本高，未重复多次实验，无法提供置信区间，可能影响结论的稳健性。
- **GRPO-Token 的简单设计**：Token 级奖励使用简单的精确匹配，而非训练专门的 Token-PRM，可能未充分发挥 Token 级监督的潜力，但作者已说明这与文本对齐的难度有关。

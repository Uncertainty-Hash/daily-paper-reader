## 摘要
在长教师轨迹上进行监督微调（SFT）是在开放软件工程（SWE）智能体中灌输探究与推理能力的主要方法。由于每个保留的响应都成为模仿目标，学生智能体会继承最终结果和中间缺陷，包括无根据的跳跃和冗余循环。高质量的训练数据必须既有效（每一步都有依据，并缩小智能体与正确修复之间的认知差距）又高效（每一步都承载信息，而非冗余或循环）。现有方法仅使用二元终端验证器来过滤或重新标记教师的运行轨迹，这种方法并未直接针对这些维度，也无法在教师失败的实例上提供监督。大多数实际问题包含由开发者撰写的参考补丁 $p^\star$，该补丁揭示了正确修复所预设的文件路径、运行时行为和编码约定，但标准流程将其丢弃。我们提出“从补丁到轨迹”（Patches-to-Trajectories, P2T）方法，它在数据整理过程中将 $p^\star$ 作为特权信息，并将轨迹构建形式化为一个关于每步有效性和轨迹长度的双目标优化问题。一个反向阶段将 $p^\star$ 提炼为一个潜在的过程图 $G^\star$，包含上下文事实和解决方案里程碑。一个正向阶段通过基于 $G^\star$ 对每步进展进行评分（在阻止信息泄漏的有根据性检查下），并从盲化的教师后续步骤中整理轨迹，保留最短的有效片段。仅使用 1.8k 个精心整理的 SWE-Gym 实例，P2T 在有效性和效率上均优于基于结果过滤的 SFT 及其工具错误掩码变体。在 SWE-bench Verified 上，它将 Pass@1 提高了最多 10.8 个百分点，同时将每个实例的推理成本降低了约 15%，并且在 SWE-bench Lite 上也取得了一致的提升。规模匹配的消融实验和定性分析进一步将轨迹质量与数据规模分离。

## Abstract
Supervised fine-tuning (SFT) on long teacher trajectories is the dominant way to instill investigation and reasoning in open software-engineering (SWE) agents. Since every retained response becomes an imitation target, the student inherits the final outcome and intermediate flaws, including ungrounded leaps and redundant loops. High-quality training data must be effective(each step is grounded and narrows the agent's epistemic gap to the correct fix) and efficient(each step is information-bearing rather than redundant or looping). Existing recipes filter or relabel teacher rollouts using only a binary terminal verifier, which does not directly target these axes and provides no supervision on instances where the teacher fails.   Most real issue includes a developer-authored reference patch, $p^\star$, revealing the file paths, runtime behaviors, and coding conventions presupposed by the correct fix, yet standard pipelines discard it. We propose Patches-to-Trajectories (P2T), which uses $p^\star$ as privileged information during curation and formulates trajectory construction as bi-objective optimization over per-step effectiveness and trajectory length. A reverse phase distills $p^\star$ into a latent process graph, $G^\star$, of contextual facts and solution milestones. A forward phase curates trajectories from blinded teacher continuations by scoring per-step progress against $G^\star$ under a leakage-blocking groundedness check and retaining the shortest effective segments.   Using only 1.8k curated SWE-Gym instances, P2T improves effectiveness and efficiency over outcome-filtered SFT and its tool-error-masking variant. On SWE-bench Verified, it raises Pass@1 by up to 10.8 points while reducing per-instance inference cost by ~15%, with consistent gains on SWE-bench Lite. Size-matched ablations and qualitative analysis further isolate trajectory quality from data scale.

# 从补丁到轨迹：面向软件工程智能体的特权过程监督

## 1. 核心问题与整体含义（研究动机和背景）

- **背景**：大型语言模型驱动的软件工程（SWE）智能体通过监督微调（SFT）在教师长轨迹上学习探究、推理与验证能力。但SFT是行为克隆目标，每一保留响应都成为模仿目标，因此中间步骤的缺陷（如无根据跳跃、冗余循环）都会被学生继承。
- **现有问题**：主流方法仅使用**二元终端验证器**（是否通过测试）过滤教师运行轨迹，这无法保证每个步骤的有效性（是否缩小与正确修复的认知差距）和效率（是否承载信息而非冗余）。此外，典型流程**丢弃了开发者编写的参考补丁 p***，而该补丁隐含了正确修复所需的前提事实、文件路径和运行时行为。
- **研究动机**：如何利用 p* 作为**特权信息**来优化轨迹构建，同时防止在轨迹中泄露答案，使学生学到真正基于证据的推理过程？本文提出 **P2T（Patches-to-Trajectories）**，将数据构建形式化为关于每步有效性与轨迹长度的双目标优化。

## 2. 方法论

- **核心思想**：将参考补丁 p* 转化为一个**潜在过程图 G***，该图由上下文事实节点和解决里程碑节点构成，节点间有前提关系的边；然后基于 G* 在轨迹构建中**对每一步的进展（覆盖了多少可发现节点）进行评分**，并**结合防泄漏的有根据性检查**，从而从盲化教师运行中整理出满足有效性阈值的最短轨迹。
- **关键技术细节**：
  - **反向阶段：过程图蒸馏**（Phase 1）
    - 使用**提议-批评**双代理循环。提议代理负责添加能填补逻辑缺口的事实或里程碑节点；批评代理负责保证**非泄漏性**（节点的解锁动作必须仅从 issue、仓库和已有节点中推理得出，不能依赖 p*）和**最小性**。
    - 节点类型：**上下文事实节点**（静态事实、动态事实）和**解决方案里程碑节点**（复现脚本、根因分析、修复计划、代码编辑、验证）。
    - 最终构建有向无环图 G*，边代表前提关系。
  - **正向阶段：后退视界双目标轨迹实现**（Phase 2）
    - 采用**滑动窗口**（窗口大小 n=10，步长 δ=5），在每个窗口内：
      1. 从盲化策略 πblind 采样 K 个长度为 n 的种子后缀。
      2. 对每个种子，允许**至多一次单步变异**：选择位置 j 和当前可用的图节点 v，用定向于 v 的解锁动作替换该步。
      3. 对每个候选段计算**段有效性 Eff**：
         - 每步进步得分 Prog_t = |∆U| / max(|A_{t-1}|, 1) × 指示器（所有新建立节点均在当前可发现集合 A_{t-1} 内）。
         - 段有效性 = (∑ Prog_t) × 有根据性门控（仅变异步需检查）。
         - 有根据性门控 = **符号引用完整性**（变异步引用的实体必须已出现在历史观察中）× **神经判断**（推理必须被历史观察蕴含）。
      4. 在候选池中应用**双目标选择**：选取有效性超过局部阈值 ηt 的候选中最短的段。若都低于阈值，退回最大有效性段。
    - 仅提交段的前 δ 步，然后重复该过程，直到智能体提交补丁。
    - 最终轨迹的补丁必须通过测试套件才能进入训练集。
- **公式**：参考 §3.3 的轨迹级优化目标和 §4.1–4.2 的每步进步得分与段有效性定义。使用 ε-约束标量方法（最短-高于-地板规则）将双目标（最大化有效性、最小化长度）转为单目标优化。

## 3. 实验设计

- **数据集与基准**：
  - 训练池：**SWE-Gym**（2,438 个真实 Python issue）。最终使用 1,815 个有工作 Docker 环境且参考补丁可通过测试的实例。P2T 产生的训练轨迹数：利用全部 1,815 个实例 (P2T full) 或随机子采样匹配基线规模 (P2T size-matched)。
  - 评估基准：**SWE-bench Verified**（500 个实例）和 **SWE-bench Lite**（300 个实例）。
- **教师模型（策展器）**：Qwen3-Coder-480B-A35B-Instruct 和 GLM-5-FP8。
- **学生模型**：Qwen2.5-Coder-14B-Instruct 和 Qwen2.5-Coder-32B-Instruct。
- **对比方法**：
  - 基线1：**测试通过拒绝采样（Test-Pass RS）**——保留完整通过测试的教师运行轨迹。
  - 基线2：**SWE-Lego**——在通过轨迹上对工具错误后的步骤掩码损失。
  - P2T 变体：size-matched、full。
- **评估指标**：**有效性**为 Pass@1（一次贪婪解码的解决率）；**效率**为每个实例的平均推理成本（以美元计，按 Qwen 官方 token 价格计算）。
- **实验设置**：使用 OpenHands 智能体框架，最大 100 轮 ReAct 回合。

## 4. 资源与算力

- **硬件**：单一节点，8× NVIDIA H200 (141 GB) GPU。
- **算力消耗**：
  - P2T 策展（1.8k 实例）约 **226 GPU 小时**（反向阶段 + 正向阶段）。

## 6. 主要结论与发现

- P2T 在**所有测试设置**下同时提升有效性和效率：在 SWE-bench Verified 上，Pass@1 提升最多 +10.8 点（Qwen2.5-C-32B + Qwen3-C-480B），推理成本降低约 15%（–$0.14 每实例）。在 SWE-bench Lite 上提升幅度类似。
- 增益**主要来自轨迹质量**而非数据规模或算力（规模匹配和计算匹配实验均支持此结论）。
- 消融结果表明：防泄漏的**有根据性检查**和**最短优先选择规则**对最终性能均至关重要。
- 反向过程蒸馏出的**过程图 G*** 携带实质性的可操作信息，其覆盖程度与解决率强相关。
- 行为克隆成功地从训练轨迹传递了结构性质：P2T 训练的学生在评估中也生成更短、更少冗余的轨迹。

## 7. 优点

- **创新性**：首次系统性地利用参考补丁作为特权信息来指导轨迹构建，同时通过过程图和防泄漏机制避免答案泄露，实现了“看答案但不让人看出答案”的训练框架。
- **形式化问题定义**：将轨迹数据构建明确建模为双目标优化（有效性 vs 效率），并给出可操作的求解算法。
- **全面的实验设计**：同时控制数据规模、算力、消融每一组件，并进行了信息价值分析和轨迹质量量化，严谨地分离了各类因素的影响。
- **实际收益显著**：仅用 1.8k 轨迹即可大幅提升 SOTA 开源模型在 SWE-bench 上的性能，同时降低推理成本，具有强实用价值。
- **方法通用性**：框架不限于代码，可推广到任何有可验证最终制品和部分可观察、工具中介的解决过程的任务。

## 8. 不足与局限

- **依赖特权信号**：需要参考补丁 p* 和可运行测试套件，不适用于缺少维护 CI 或无法获得官方补丁的问题。
- **LLM 中介的保证不严格**：非泄漏性批评器、有根据判断器、节点建立验证器均由 LLM 实现，虽在实验中有效，但缺少形式化保证，可能存在个体失误。
- **策展算力开销较大**：1.8k 实例需要 ~226 GPU 小时，虽然算力匹配实验证明其优越性，但对于资源有限的团队仍为门槛。
- **通用性待验证**：仅使用 OpenHands 框架和 Qwen2.5-Coder 学生系列，未在 Agentless、浏览器增强智能体或其他代码模型族上验证。
- **语言与任务范围**：仅覆盖 Python issue，未在其他编程语言或非代码任务（如定理证明、科学协议）上测试。
- **潜在过适应**：SWE-bench 测试集可能存在数据泄露或弱测试，虽论文引用相关审计（Aleithan 2024），但未测试外部基准。
